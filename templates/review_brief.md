## 대조 항목

**문서(분석서·PRD·명세·지시서)일 때**
1. 근거: 무작위 10곳 이상의 `파일:행`을 원본에서 열어 값이 맞는지
2. 누락: 원본에 있는데 문서에 없는 화면·API·저장 키·플랫폼 연동·상태
3. 결정: 어느 OS 사용자든 지금 되는 일을 못 하게 되는 결정이 있는지
4. 일관성: ID 중복, 문서 안 모순, 역참조 누락(지시서)

**코드(모듈)일 때**
1. 레이아웃: 요소 존재·순서, 기준·offset·크기, safe area, 스크롤
2. 요소: 텍스트 토큰·색, 줄 수·말줄임, 문자열 키(옛 키·하드코딩이면 결함), 에셋
3. 상태: 기본·비활성·로딩·빈·오류·결과 미확정
4. 인터랙션: 탭 목적지, 로그인 가드, 뒤로가기(Android 하드웨어·iOS 스와이프), 키보드, 중복 탭 잠금
5. 결정 준수: 연결된 D·U 결정이 코드에 구현됐는지
6. 아키텍처: domain 순수, Controller 비즈니스 규칙 없음, 범위 밖 파일 수정 없음
7. 보안: 비밀값 원문, 토큰·카드·비밀번호 로그
8. `dart analyze <폴더>` 실행 결과

## 판정
- **결함(필수 수정)**: 기준과 다른 값·키·상태·목적지, 빠진 요소, 근거 오류, 사용자 차단 결정
- **경미**: 허용 범위 차이, 시각 결과 같은 구현 차이
- **기준 문서 문제**: 명세·PRD 자체의 누락·모순(구현 결함 아님)
- 실기기 확인 항목은 결함이 아니다.
