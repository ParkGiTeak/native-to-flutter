# 10단계 — 유지보수 문서

목표: 전환 과정 문서(PRD·명세·로그)를 몰라도 새 개발자가 Flutter 프로젝트를 유지보수·확장할 수 있게, 프로젝트 안 `docs/`에 **현재 코드 기준** 문서를 만든다. 전환 문서는 "왜 이렇게 됐는가"의 근거로만 링크한다.

## 1. 문서 구성

| 파일 | 내용 |
|---|---|
| `docs/README.md` | 문서 목록(언제 보는지), 처음 읽는 순서, 전환 과정 문서 안내, 문서 갱신 규칙 |
| `01-architecture.md` | 레이어, feature 목록, DI, 라우팅·가드, 세션, 로컬 저장, 부트스트랩, 에러 모델, 네비게이션 주의점 |
| `02-conventions.md` | 설계 원칙(현재 동작이 기준·변경은 사용자 결정, 사용자 결정 요약 — 전환 때의 기준 OS 원칙은 "이력"으로만 적고 현행 규칙으로 쓰지 않는다), MVI 규칙과 예시, 도메인 규칙, 코딩·네이밍, 문자열 키 규칙, 테스트 전략·커버리지 게이트, 새 기능 추가 절차, 문서 갱신 관례 |
| `03-design-system.md` | 토큰, 공용 컴포넌트 사용법, 화면 전환, 에셋, 문자열 사용법 |
| `04-api.md` | 네트워크 구성·인터셉터, 인증·토큰 갱신, 암호화, 오류 매핑·표시 규칙, 전체 API 목록, 서버 계약 주의점 |
| `05-screens*.md` | 화면별 라우트·진입·상태·동작·규칙(화면 수가 많으면 2개 파일로) |
| `06-platform.md` | 어댑터별 정의, 네이티브 코드, 권한 흐름, 메서드 채널 목록, 바꿀 때 확인할 것 |
| `07-build-release.md` | flavor, env, 서명, Firebase, 실행·빌드 명령, CI, 품질 게이트, 버전 규칙, 트러블슈팅(이번 전환에서 실제로 겪은 문제) |

프로젝트 `README.md`는 짧게: 앱 소개, 스택, 빠른 시작 명령, 폴더 구조, 문서 표, 저장소 정책 경고.

### 프로젝트 `CLAUDE.md`

문서만 만들어 두면 새 세션의 에이전트는 읽지 않고 코드부터 고친다. Flutter 프로젝트 루트에 `CLAUDE.md`(60줄 안팎)를 만들어 세션마다 자동으로 읽히게 한다. 내용은 복사하지 않고 가리키기만 한다(복사하면 docs와 어긋난다).

1. 앱 한 줄 소개, 스택
2. **작업별 문서 안내 표**: 새 기능 → `02` 추가 절차, 화면 수정 → `05` 해당 절 + `03`, API → `04`, 네이티브·권한·푸시 → `06`, 빌드·서명 → `07`
3. **어기면 안 되는 규칙만**: 현재 동작이 기준(전환 때의 기준 OS 원칙은 끝났음을 명시), 계층·MVI 규칙, 문자열 키, 공용 컴포넌트, 결과 미확정 요청 재전송 금지, 비밀값·저장소 정책
4. 실행·검증 명령, 설치 주의점
5. **작업 후 할 일**: 테스트, analyze·커버리지 게이트, `docs/` 갱신, 사용자 결정 U 번호 기록

## 2. 진행 (작성 → 리뷰 → 수정 → 교차 검토)

1. 카테고리별 작성 에이전트(Opus) 병렬. 각자 **코드를 직접 읽고** 쓴다. 전환 문서는 근거 확인용.
2. 문서마다 리뷰어(Fable)가 코드와 대조: 없는 클래스·잘못된 경로·틀린 수치·빠진 주제. 결과는 `approve / needs_fix + 이슈 목록(심각도, 위치, 근거)`.
3. 수정 에이전트가 각 이슈를 **코드로 재확인**한 뒤 반영하거나, 리뷰가 틀렸으면 근거와 함께 반려.
4. 전체 교차 검토(리뷰어 1개): 문서 간 모순, 중복 규칙(한 곳에만 정의하고 나머지는 링크), 빠진 주제, 경로 표기 통일.
5. 오케스트레이터가 링크 검사(모든 상대 링크가 실제 파일을 가리키는지)와 마크다운 오인 표기(예: `[취소](닫기)`처럼 버튼 표기가 링크로 렌더링되는 것) 확인 후 README 작성.

이 흐름은 Workflow 도구 파이프라인(write → review → fix → cross-check → cross-fix)으로 돌리기 좋다.

## 3. 원칙

- 코드와 문서가 다르면 코드가 기준이다. 문서 상단에 기준 날짜를 적는다.
- 같은 규칙을 여러 문서에 복사하지 않는다.
- 트러블슈팅은 실제로 겪은 증상·원인·조치·회귀 테스트 위치로 쓴다.
