# 실제 전환에서 터진 문제와 예방법

실제 iOS·Android → Flutter 전환에서 겪은 문제를 일반화했다. 해당 영역을 구현·검토할 때 확인 목록으로 쓴다. 특정 라이브러리 이름이 나오는 항목은 같은 성격의 다른 라이브러리에도 적용된다.

## 프로세스

| 문제 | 예방 |
|---|---|
| 기능을 먼저 구현하고 UI를 나중에 원본에 맞추느라 전 화면을 두 번 수정 | 디자인 명세(3단계)를 구현 전에 확정 |
| 원본 안내 문구가 실제 동작과 다르다고 판단해 임의로 삭제 → 사용자가 복원 요청 | 문구·기능 제거는 사용자 결정 |
| 원본에 없던 상용 보안 SDK와 그 설정값(알림 메일 등)을 도입 → 사용자가 원본 방식으로 되돌리라고 함 | 원본 방식 이식이 기본. 새 SDK·서비스는 묻고 도입 |
| 다른 작업 흐름에서 바뀐 코드가 문서에 반영되지 않음 | 라운드마다 코드 → 문서 동기화. 사용자가 "다른 작업 완료"라고 하면 변경 파일을 찾아 문서 갱신 |
| 결정 ID 중복(같은 번호를 두 항목에 부여) | 새 ID 부여 전 grep |
| 병렬 에이전트가 같은 공통 파일을 고쳐 충돌 | 범위 소유권 + 공통 요청 보고 |
| 리뷰 지적 수치가 틀림(주석까지 센 grep 결과) | 지적도 코드로 재확인 후 반영 |

## 네비게이션·상태

| 문제 | 예방 |
|---|---|
| 애니메이션 없이 화면을 닫으려고 `Navigator.removeRoute`를 쓰자, 라우팅 라이브러리(GetX 등)의 "현재 경로" 기록이 갱신되지 않아 같은 경로로 다시 이동이 무시됨(버튼이 안 눌리는 것처럼 보임) | `didRemove`에서 현재 경로를 보정하는 NavigatorObserver를 전역 등록. 회귀 테스트: "열기 → 취소(remove) → 같은 버튼 다시" |
| 로그아웃·세션 만료 후 홈으로 갔는데 버튼이 반응하지 않음 | 스택을 비우고 홈으로 가는 공통 함수(reset to home) 하나로 통일하고 라우팅 상태까지 초기화 |
| 비회원 → 로그인 후 홈이 비회원 UI 그대로 | 세션 변경 이벤트를 홈이 구독해 재조회 |
| 화면 복귀 시 재조회 누락(원본 `viewWillAppear`/`onResume`) | 분석서에 복귀 시 동작을 기록하고 라우트 복귀 콜백으로 구현 |
| 로딩 중 뒤로가기로 화면이 닫혀 응답 처리 꼬임 | 로딩 중 시스템·제스처 뒤로가기 차단 정책을 명세에 명시 |

## 데이터·네트워크

| 문제 | 예방 |
|---|---|
| 서버 날짜 문자열에 시간대가 없음 → 기기 시간대로 해석해 만료 판정이 틀림 | 서버 시간대(예: KST)로 해석하는 함수 하나로 통일 |
| 페이징 파라미터를 바디로만 보내 서버가 무시 | 원본이 실제로 보내는 위치(쿼리/바디)를 그대로. 계약 테스트로 고정 |
| 원본 한쪽은 네트워크 실패 시 콜백이 안 와 무한 대기 | 모든 요청은 성공 또는 실패로 끝나게 인터셉터에서 보장 |
| 결제·등록 타임아웃 후 자동 재시도로 중복 처리 위험 | 결과 미확정 상태, 자동 재전송 금지, 확인 경로 |
| 외부 호스트(지도·검색 API, QR 안의 URL)에도 인증 토큰 첨부 | 토큰은 자사 호스트 화이트리스트에만 |
| 필드 암호화 결과가 원본과 다름 | 원본 암호문으로 바이트 단위 테스트 벡터 |
| OS별 푸시 payload 키 표기가 다름(대소문자) | 수신 시 두 표기 모두 허용 |
| 웹뷰 본인인증의 JS 브리지 방식이 OS별로 다름 | 두 브리지 모두 수신, 결과 DTO는 엄격 파싱 |
| 목록 응답에 만료 항목이 섞여 옴 | 거른 결과 빈 페이지면 다음 페이지 조회(상한), 전체 개수 보정 |

## UI

| 문제 | 예방 |
|---|---|
| 지도 마커·아이콘이 흐림 | 에셋 배율 변형(2x/3x) 포함, 마커는 기기 배율로 생성 |
| 시스템 글자 크기에 따라 레이아웃 깨짐(원본은 고정 pt) | 글자 배율 정책을 결정(U)하고 앱 루트에서 적용 |
| 입력칸 밑줄 등 Material 기본 장식이 원본과 다름 | 테마에서 기본 장식을 명세값으로 덮고, 화면별 예외는 명세에 |
| 원본 OS 네이티브 화면(OCR·카메라) 앞에 Flutter 안내 화면이 끼어 깜빡임 | 네이티브 화면을 바로 띄울지 결정(U) |
| 권한 거부 후 설정에서 허용하고 돌아왔을 때 아무 일도 안 일어남 | 앱 복귀 시 권한 재확인 후 원래 동작 이어 하기 |

## 빌드·서명·플랫폼

| 문제 | 예방 |
|---|---|
| release 빌드가 조용히 debug 키로 서명 | 서명 미설정 시 경고 배너 + CI에서 debug 인증서 거부 |
| debug ↔ release 서명이 달라 설치 실패, 재설치하면 데이터 삭제 | 사용자에게 미리 알림. 이관 테스트는 같은 서명으로 `install -r` |
| Xcode 계정 없이 자동 서명 실패 | 수동 서명 + 포털에서 받은 Development 프로필 |
| 와일드카드 프로필에 푸시 capability 없음 | 명시적 App ID 프로필, entitlements 환경 짝 맞추기 |
| 외부 SDK 라이선스가 앱 ID에 묶여 flavor별 앱 ID를 쓸 수 없음 | 착수 때 확인. 공통 앱 ID면 동시 설치 불가·flavor 전환 시 데이터 잔존을 문서화 |
| iOS flavor 구성 후 `pod install`·Firebase 설정 누락 오류 | Podfile 구성 매핑, 구성별 xcconfig의 Pods include, 구성 이름 끝 = flavor 규칙(`07-release.md` 4절) |
| Firebase·외부 연동에 업로드 키 해시만 등록해 스토어 빌드에서 실패 | 업로드 키와 Play 앱 서명 키 SHA-256 모두 등록 |
| Flutter 저장소 패키지로 원본 로컬 데이터를 읽으려 함(못 읽음) | 네이티브 코드로 원본 UserDefaults·Keychain·SharedPreferences 읽기 |
| `flutter run` 명령이 길어 불편 | IDE 실행 구성 커밋, README에 명령 표 |
| release에서만 플랫폼 채널 타입 오류(R8 난독화) | JNI·채널 경계 클래스 keep 규칙 |
| 보안 검사를 prod에서 켜자 prod debug 실행 차단 | 디버거 감지는 release에서만 차단 |
| 보안 검사 채널 오류로 앱이 막힘 | 채널 오류·타임아웃은 통과(fail-open)하고 로그만 |
| iOS debug 빌드를 홈 아이콘으로 열면 실행 안 됨 | 단독 확인용은 release/profile로 설치 |
| 여러 flutter 프로세스가 같은 `build/`를 써서 툴 크래시 | 전체 테스트·빌드는 한 번에 하나만 |
| 사용하지 않는 함수가 커버리지 게이트를 깨뜨림 | 쓰지 않는 코드는 지운다 |
| 시간 의존 테스트 픽스처가 특정 시각 이후 실패 | 시계 주입, 하루 끝 같은 안전한 기준 |
